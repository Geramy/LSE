# M8 Q4 down projection and prefill memory lifetime

## Scope

Measured on macOS, R9700/gfx1201, Qwen3.8-27B group-affine Q4 target and Q8 DFlash2 block8. BF16 target KV and FP32 floating accumulation. All seven proposals remain active. Gate/up and other projection shapes retain their accepted schedules.

The selected WMMA shape is M8/N5120/K17408, group64, WG256. A shared U32 activation panel stores four K16 fragments and interleaved scale/sum words. It pads eight input rows to 16 with zeros. The consumer executes INT32 matrix products and restores each group's affine terms into FP32. It preserves compact Q4 weights; it does not duplicate the weight allocation.

## Native kernel result

Including panel preparation, paired DOT4 takes 0.265559ms and WMMA takes 0.189158ms: a 28.77% reduction. Passive GPU timestamp means are 0.244294ms and 0.168680ms. The consumer uses 52 VGPR/23 SGPR, zero LDS and zero private scratch; the producer uses 27 VGPR/20 SGPR and zero private scratch.

The native integration fixture passes complete eight-row contraction, exact panel codec, padding, residual epilogue, zero replay, readonly inputs and buffer guards. The maximum component error against the independent group64 oracle is 5.96046448e-8. This fixture checks arithmetic and memory safety; perplexity checks model quality.

The same layout loses on the gate/up shape. That losing variant is absent from production. The existing faster paired DOT4 gate/up path remains active.

## Matched HTTP result

Two exact 1024-token prompts, 384 generated tokens each, temperature 0.6, top-k 20, top-p 0.95, seed 1234, batch/ubatch 1024, seven proposals. Each arm starts with an empty private cache. The second request runs in the resident process, has a different leading user token and reuses zero prompt KV. It can still compile previously unseen kernels. Timings include that compilation. Zero host execution and fallback in all requests.

The 29 TPS baseline, 49 TPS MTP, 103 TPS DFlash2 and 600 PP/s targets remain unmet.

## Completed prefill memory

Commit 20d5c1e releases completed prefill graphs before decode, while retaining materialized recurrent state, paged KV, weights and compiled kernels. DFlash2 cold reset also releases completed context graphs. Allocation errors now preserve their status and requested byte count.

Previously, request 1 grew KV 4096→8192 and incidentally dropped the 4096-row prefill workspace. Request 2 already had an 8192 pool, retained that workspace and failed a 64 MiB allocation during decode. Both exact 4096-token requests now complete: 435.02/479.10 PP/s and 36.30/31.88 TPS. These establish removal of the reproduced allocation failure, not faster throughput or a measured peak-VRAM claim.
