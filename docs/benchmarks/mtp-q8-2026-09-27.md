## Initial DFlash2 HTTP check

The opt-in Q8 DFlash2 path completed two GPU-only HTTP requests with identical
continuations. A fixed 1024-token prompt, 16 generated tokens, greedy sampling,
KV capacity 2048 and the same 64 us HSA wait were used. The warm request had no
new JIT compiles and measured **421.29 PP/s, 14.62 TPS**, with 10/13 compared
proposals accepted, five verifier passes, 200.10 ms draft/context work and
788.16 ms verification. The cold request included 32.36 seconds of JIT.
These results use a shorter continuation than the MTP table and are not a
controlled comparison. DFlash2 remains opt-in; 43 TPS has not been reached.

Its seven-row vocabulary top-k component (248320 logits, K16) dropped from
663.126584 ms to 2.950625 ms: 224.74x faster in a five-run warm host-wall median.
Complete finite values and original indices matched both the old GPU path and
an independent CPU oracle, with zero host groups or fallbacks. This component
speedup is not an engine throughput multiplier.

## Passive CPU/GPU profile

A separate MTP=2 run captured command-processor timestamps and an eight-second
CPU sample with dispatch profiling enabled. It used the same 1024-token prompt,
32 generated tokens, KV 2048, greedy sampling and 64 us wait. After two warmups,
the measured request delivered 441.89 PP/s and 19.93 TPS with no new JIT compile.
This instrumented run is separate from the unprofiled throughput table.

Dispatch ordering isolated 15 complete three-row target verifier passes plus one
single-row tail; draft and prefill dispatches were excluded. Total target CP
execution summed to 1222.34 ms, target dispatch envelopes to 1345.89 ms, and host
verification to 1421.64 ms. Three-row passes contained 1669 dispatches each.

| Three-row target operation | CP duration ms | Share of three-row device time |
|---|---:|---:|
| FFN up/gate |326.20|27.49%|
| FFN down |223.63|18.85%|
| Short paged attention |258.38|21.78%|
| All quantized projections, including FFNs |827.38|69.73%|

The attention calls averaged 1076.59 us across 240 dispatches, with only 24
workgroups per call. The Flash8 source emits eight query-row loops for three
live rows and reserves 24704 B LDS. This identified the short-query split
work measured in the next section; the profile alone does not establish its gain.

The CPU sample placed 1073 of 1229 verifier snapshots inside an HSA signal wait.
These are sampled stack counts, not CPU utilization percentages. The capture has
no occupancy counters, no correlation between CPU/GPU clock origins, and no
matched profiling-overhead measurement. Summed kernel durations are not a GPU
busy-time metric.

At unchanged accepted outputs, removing every measured three-row attention
operation would bound this instrumented sample at roughly 23.90 TPS. Halving
both its FFN and attention time would yield roughly 26.93 TPS. Reaching 43 TPS
requires additional projection or acceptance gains beyond that attention work.
